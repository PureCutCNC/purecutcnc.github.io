Select a machine before exporting. Its output dialect determines whether you export G-code
or a ShopBot part file. The definition also controls machine-specific capabilities, such as
canned drilling cycles.

## Before you start

- Confirm the controller and machine you will actually use.
- Read [Working safely](/guide/start-here/safety/) before exporting a program for a real machine.

## Select a machine

<Steps>

1. Select the **Project** node in the feature tree.

2. Choose the machine in the **Machine** property. Its badge identifies whether it is a built-in
   definition, a project copy, or needs attention.

3. Generate and inspect the toolpaths again, then export a test program for the selected machine.

</Steps>

## Library

Open **Manage machines** to browse built-in definitions, including **Generic**, and **My Machines**. A project stores a
copy of its selected definition, so a project remains reproducible when your personal library
changes. Import a definition into the manager when it is not already available.

### My Machines

The list shows each machine's kind as a small icon, router or plasma torch, and a rotary icon
on machines with a rotary axis; the legend under the list reads **Router**, **Plasma**, and
**Rotary**. The group headings separate the built-in machines from **My Machines**.

<VisualPending id="m8-machine-list" />

Personal definitions live in **My Machines**. Share a definition by exporting it from the manager
and import it into another library; older projects keep their own selected project copy.

### Badges

The machine badge distinguishes a built-in definition, a personal definition, and a project copy,
and it draws attention to definitions that need review.

## Updates

When a definition used by a project has changed, the app shows an update notice. Compare the
project copy with the available definition before accepting an update; a changed post-processor
can change emitted G-code.

For a G-code machine, the editor groups a definition into **General**, **Program**, **Tool change**, and **Coolant**.
It also provides raw JSON, a variables reference, and validation feedback. Use the editor only
when you understand the controller requirements for every changed field.

<Aside type="danger" title="Safety: a machine definition changes machine output">
	Do not assume that a generated program is safe merely because it parses. Review the machine,

	then dry-run it on the real controller.

## Rotary axis

<Availability kind="preview" />

For a router machine that writes G-code, the editor offers **Rotary axis**: **None** (default),
**Bar along X**, or **Bar along Y**. Match the stock's **Axis**. The built-in rotary machines
need no setting here: they take the orientation from the stock (see
[Built-in rotary machines](#built-in-rotary-machines)). **Driven by** offers **Its own
axis (A)** or the other horizontal motor: **The Y motor** for X stock, **The X motor** for Y stock.
The **Program word: A** note changes to the borrowed letter; **Reverse direction** starts off.

**Zero A line (optional)** runs before every rotary operation. Use a line that only sets the
rotary zero, without moving: `G92 A0`, or `G10 L20 P… A0` in the work coordinate system the
program uses, with this machine's rotary letter. Leave it empty to have the program pause
between rotary operations so you can zero A by hand. See
[Rotary export](/guide/rotary/rotary-operations/#rotary-export).
For an own axis, tick **Controller scales A with inch units: rotary programs are exported in mm
only** when the controller turns A like a length under G20. A borrowed motor always reads the
angle as a length, so the editor notes that its rotary programs are exported in mm only.
The **Manage machines** preview includes a **Rotary axis** row summarising this choice.
See [Rotary machining](/guide/rotary/overview/#machine-rotary-axis) and
[Rotary definition](/guide/reference/machine-definitions/#rotary-definition).

<Screenshot src={rotaryAxis} maxWidth={376} alt="Rotary axis group in the machine editor: Rotary axis Bar along X, Driven by The Y motor, Program word: Y, Reverse direction, and an empty Zero A line (optional) field" caption="A rotary that borrows the Y motor is programmed with Y words." />

### Built-in rotary machines

Six built-in machines carry a rotary axis:

| Machine | Rotary | Setup notes from its description |
| --- | --- | --- |
| **GRBL 1.1 + rotary (borrowed motor)** | The Y motor for a bar along X, the X motor for a bar along Y | Set that axis's steps/mm as steps per degree; soft limits off (`$20=0`). mm only. |
| **GRBL 4-axis fork + rotary A** | Own axis A | Grbl 1.1 fork boards with a fourth axis. Soft limits off (`$20=0`) or `$133` past any job; in gSender enable **Use A-axis for grbl**. mm only. |
| **grblHAL + rotary A** | Own axis A | Put A in the rotary axes setting (`$376`); soft limits off (`$20=0`) or `$133` past any job. |
| **Mach3 + rotary A** | Own axis A | Tick A as angular, turn Rot 360 rollover off, and turn A soft limits off. |
| **UCCNC + rotary A** | Own axis A | UCCNC 1.2105 or later (G93). Turn the 360° rollover and A soft limits off. |
| **LinuxCNC + rotary A** | Own axis A | Set `[AXIS_A]` limits wide and leave `WRAPPED_ROTARY` off. |

A counts past 360° in every rotary program, so rollover and A soft limits must not stop it.
These machines follow the project's bar: one machine serves a bar along X or along Y. The
manager summary reads, for example, **Follows the bar (now along X), on its own axis (A)**, and
the export dialog names the axis it turns about (and, for the borrowed motor, the motor). A copy
saved or duplicated from one gets the open project's axis as a fixed **Bar along X** or **Bar
along Y**.

The borrowed-motor GRBL machine and **GRBL 4-axis fork + rotary A** turn the rotary in mm only.
In an inch rotary project the machine picker and the export dialog show the machine's name followed by
**turns the rotary in millimetres only. Change the project units to mm to export rotary
operations.**, and its turning operations are not exported.

## Plasma machines

<Availability kind="experimental" />

For G-code machines, **Machine kind** offers **Router** or **Plasma**. The built-ins include
**QtPlasmaC (experimental)** (`.ngc`) and **Grbl plasma (OpenBuilds CONTROL) (experimental)**
(`.gcode`). Choose the one that matches your controller. Plasma authoring follows the
project's **Plasma** type; a missing or unsuitable machine prevents export.

Under **Plasma settings**, **Torch on command** and **Torch off command** control the torch.
**THC on command (optional)** and **THC off command (optional)** describe torch height control.
**Pierce mode** determines who owns probing and the pierce sequence:

| Mode | Fields and behaviour |
| --- | --- |
| **Controller owns piercing** | QtPlasmaC uses **Material select command**, **Material wait command**, and **Material feed command**. The controller's material table owns heights, delay, feed, and THC. Set the tool's local material number before exporting. |
| **G-code owns piercing (touch-off before each cut)** | Grbl plasma probes before each cut, establishes sheet Z zero, then uses the torch's pierce height, delay, cut height, and plunge feed. |

G-code piercing shows **Probe command**, **Probe depth below Z zero (mm)**,
**Probe feed (mm/min)**, **Set Z zero command**, and **Touch-off switch offset (mm)**.
The built-in values are `G38.2`, 30 mm, 100 mm/min, `G10 L20 P0`, and 0 mm respectively.
Depth and feed must be positive. A blank offset means zero. Use zero for a probe that trips
at the sheet surface; otherwise measure your switch offset. These machine fields stay in
millimetres and mm/min even for inch projects.

The controller-owned editor still contains hints describing plasma output as unimplemented.
Those hints are out of date: [plasma export](/guide/verify-export/gcode-export/#plasma-programs)
writes the material handshake and torch motion.

## ShopBot machine

<Availability kind="preview" />

Select **ShopBot (SBP)** for a native ShopBot part file. In its editor, **General** contains
**Name** and **File extension** with a note explaining that PureCutCNC writes the whole program.
There are no G-code unit commands, program templates, tool-change, coolant, or variables
sections. **Advanced (raw JSON)** holds axis mapping, number format, and arc support.
Duplicating this machine keeps its ShopBot output dialect. See
[ShopBot part files](/guide/verify-export/gcode-export/#shopbot-part-files).

## Template rules and retained machines

<Availability kind="preview" />

Only tool-change and end-of-program templates may contain arbitrary motion. The program header
allows modal setup, including a bare `G0` or `G00` without axis words and `G91.1` for incremental
arc centres. It refuses `G90.1`, `G91`, and axis words. Other templates are limited to their
purpose; spindle, coolant, pause, and operation-header templates must not move an axis or
change motion modes. See [Template rules](/guide/reference/machine-definitions/#template-rules)
for placeholders and command fields.

A saved project machine that breaks a rule is kept, with a warning on open. The manager and
editor list each offending template, line number, line text, and rule. Export lists the same
problems and stays blocked until the machine is corrected. Review and repair the project copy
explicitly; do not assume that reopening the project repaired it.

A project's custom machine is not automatically added to **My Machines** on open. When absent
from that library, it shows **Not in my machines** with **Save to my machines**. Use that button
to keep a personal library copy.
